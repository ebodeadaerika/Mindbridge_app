## What Is This Project?

**MindBridge** is a full-stack student mental health and wellbeing platform built as the final exam project for:
- **Course:** SEN3244 — Software Architecture
- **Instructor:** Engr. TEKOH PALMA
- **University:** ICT University of Cameroon
- **Semester:** Spring 2026
- **Duration:** 8 weeks
- **Team size:** 4 members (max allowed)

The project must solve a real-world problem and incorporate specific architectural requirements worth 105 marks total.

---

## The Problem MindBridge Solves

University students across Sub-Saharan Africa face significant mental health challenges — exam pressure, financial stress, social isolation — but there is virtually no structured, accessible, stigma-free support system on most campuses. Students suffer in silence because:
- Visiting a counselor carries social stigma
- There is no anonymous way to express distress
- No system tracks whether students are actually okay
- Mental health resources are scattered or nonexistent

**MindBridge bridges this gap.**

## Architecture Style (CONFIRMED)

**Layered (N-Tier) Architecture:**
```
Presentation Layer     → React/TypeScript frontend + Swagger UI
API / Routes Layer     → FastAPI route handlers & middleware
Business Logic Layer   → Services (MoodService, AIService, etc.)
Data Access Layer      → SQLAlchemy ORM + Repository pattern
Database Layer         → PostgreSQL
```

**Why Layered:** Small team, 8-week deadline, clear separation of concerns, easy to test, honest and well-argued for the examiner.

## Database Models (5 tables)

1. **User** — id, name, email, password_hash, role (student/admin), created_at
2. **MoodLog** — id, anon_token (NOT user_id), mood_score (1-5), energy_level (1-5), note, date
3. **JournalEntry** — id, user_id, title, body, created_at
4. **ForumPost** — id, anon_name, body, created_at
5. **CrisisFlag** — id, severity (low/medium/high), message, resolved, created_at

**CRITICAL PRIVACY RULE:** MoodLog uses anon_token not user_id. Admins can NEVER trace mood logs to individual students.

## Innovation Feature

**AI Wellness Companion** — POST /ai/chat endpoint that:
- Accepts student message + conversation history
- Uses Claude API or OpenAI API
- System prompt instructs AI to respond with empathy
- Never diagnoses medical conditions
- Always includes crisis resources if self-harm is detected
- Conversation NOT stored on server (privacy)
